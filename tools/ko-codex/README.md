# 국어 Codex 연결 — Better-BMAPS 시험 기능

기존 국어 화면의 `분석`은 그대로입니다. 새 `Codex 분석`은 **같은 PC**에서 실행 중인 로컬 처리 프로그램으로 PDF를 보내고, Python 원본 영역 추출 → Codex 원본 검토 → 등록 초안 미리보기를 수행합니다. 이 채팅창에 메시지를 보내는 방식이 아닙니다.

## 실행

1. Python과 Codex CLI를 준비하고 `python -m pip install -r requirements.txt`, `codex login`을 실행합니다. 기존 ChatGPT 로그인을 재사용합니다. 별도 API 키를 코드에 넣지 않습니다.
2. 최초 한 번 Better-BMAPS 체크아웃에서 아래 명령으로 사용자 로그인 시 자동 실행을 설정합니다. 주소는 사용하는 테스트 사이트의 HTTPS 주소입니다.

   ```powershell
   ./tools/ko-codex/install-startup.ps1 -Origin 'https://실제-Better-BMAPS-주소'
   ```

3. 사이트의 `Codex 연결`을 누르고 열린 로컬 창에서 요청 사이트 주소를 확인한 다음 `이 사이트 연결 허용`을 누릅니다. 연결 코드 입력과 CMD 창 유지가 필요 없습니다. 사이트에 `Codex 연결됨 · 창 닫기 가능`이 표시되면 승인 창을 닫아도 됩니다. 브라우저가 로컬 네트워크 권한을 물으면 허용하세요. 직접 통신이 차단되면 팝업 유지가 필요하다는 안내가 표시됩니다. 팝업이 차단되면 브라우저에서 허용해야 합니다.
4. PDF와 문항 범위를 선택하고 `Codex 분석`을 누릅니다. 첫 시험은 작은 범위로 진행하세요. 전 범위를 검사하면 여러 번의 Codex 호출과 계정 사용량이 발생합니다.
5. 결과에서 원본 지문·문항 이미지와 Codex 검토 의견을 확인하고 `등록 초안 내려받기`로 JSON을 보관합니다.

페이지를 새로고침했다면 다시 연결을 허용하고 `결과 다시 받기`를 누릅니다. 처리 프로그램 자체를 재시작한 경우 새 분석이 필요합니다. 한 번에 한 작업만 처리합니다. 로컬 창의 종료 버튼으로 처리 프로그램을 종료할 수 있습니다. PC가 켜져 있고 Windows에 로그인되어 있어야 합니다.

자동 실행 해제는 같은 설치 명령에 `-Remove`를 추가합니다. 수동 백그라운드 시작은 `start.ps1 -Origin 'https://실제-Better-BMAPS-주소' -Background`입니다. 설치된 바로가기가 이 체크아웃을 참조하므로 폴더를 이동하면 재설치하세요. 시작 오류는 사용자 폴더 `.bmaps-ko-worker/worker-error.log`에서 확인합니다. 이전 연결 코드 방식은 고급 설정에 남겨 두었습니다.

## 현재 범위

- 텍스트형 PDF, 최대 30MB/40쪽. 문제 범위는 기존 화면 값을 따릅니다.
- Python이 각 단·페이지의 영역을 결정합니다. Codex는 선택 범위의 모든 원본 페이지를 네 쪽씩 검토하여 누락·잘림·연결 문제를 보고합니다. 자동 수정 또는 정확성 보장은 없습니다.
- Codex 실패를 성공으로 표시하지 않습니다. 로그·페이지 이미지·완료 결과는 로컬 사용자 폴더 `.bmaps-ko-worker/<작업ID>`에 남습니다. 보관이 필요 없으면 프로그램 종료 후 해당 작업 폴더를 삭제하세요.
- **등록·발행·학생 응시:** 베티모의고사와 같은 흐름입니다. `migrations/20261012_korean_exams.sql` 에 이어 `migrations/20261013_korean_exams_v2.sql` 을 Supabase 에서 한 번 실행해야 합니다. Codex 분석 결과를 `bety-admin.html` 국어 탭의 선택한 시험지에 적용하면 지문·문항 원본 이미지가 `bety-exam/ko-published/<시험지ID>/` 에 저장됩니다. 정답 PDF 는 공개 저장소로 전송하지 않습니다.
- 다른 PC에서 작업 요청을 보내는 HQ 큐는 아직 없습니다. 로컬 서버는 `127.0.0.1:8765`에만 바인딩하며 인터넷에 공개하거나 LAN 주소로 변경하지 마세요.
- 로컬 창은 사용자 승인 후에만 요청한 사이트와 통신하며 메시지의 Origin과 창을 검증합니다. 프로그램의 원본 인증 코드는 로컬 창에만 둡니다. 승인한 HTTPS 출처에만 유효한 별도 임시 토큰을 사이트 메모리에 전달하고, 직접 통신을 확인한 뒤 팝업 없이 처리합니다. 임시 승인은 최대 12시간 또는 처리 프로그램 종료까지 유효하며, 페이지 새로고침 시 재연결해야 합니다. 승인 창의 연결 해제는 해당 토큰을 서버에서 회수합니다. 브라우저가 직접 통신을 차단하는 환경에서는 팝업 중계를 유지하며 이를 표시합니다. 서버는 Host와 인증 코드를 검증하고 외부 프레임 삽입을 차단합니다. 문서는 고정된 검토 프롬프트에 데이터로만 전달하고 Codex는 읽기 전용으로 실행합니다. 로그인 인증 파일이나 연결 코드를 저장소에 올리지 마세요.

공식 방식: https://developers.openai.com/codex/noninteractive

## 국어 시험 등록 및 응시 (베티모의고사와 같은 흐름)

1. 사용자가 SQL(`20261012` → `20261013_v2`)을 실행한 뒤 `bety-admin.html` 국어 탭을 새로고침합니다. 기존 수학 시험 테이블·RPC 는 변경하지 않습니다.
2. **1️⃣ 회차** — 국어 전용 회차(`weekend_sessions` program='korean')를 추가하거나 고릅니다.
3. **2️⃣ 시험지** — 학교급·학년·선택과목(화법과 작문/언어와 매체/공통)·제한시간·발행 여부를 정합니다. 응시 대상은 학생을 고르지 않고 **베티 참여(bety_yn) 학생 중 학교급·학년이 맞는 학생**이 자동으로 됩니다(서버 `ko_eligible`).
4. **3️⃣ 세팅 › PDF 가져오기(Codex)** — Codex 분석 완료 → (정답 PDF 가 있으면 자동) 정답·배점 표 확인 → `시험지에 적용`. 시험지의 선택과목에 맞는 문항만 들어가며, 지문·문항의 원본 영역을 각각 한 장으로 합쳐 올립니다. 빈 정답이나 중복 번호가 있으면 적용을 막습니다.
5. **정답 · 배점** 탭에서 나중에 고칠 수 있고, **응시 현황** 탭에서 점수·상태를 보고 초기화할 수 있습니다.
6. 학생은 `bety-omr.html`(BMAPS 로그인 공유)에서 수학 회차와 같은 목록에 뜨는 `📖 국어` 회차를 골라 응시합니다. 한 문항씩 넘기며 `📖 지문` 버튼으로 공통 지문과 문항을 오갑니다. 서버 기준 제한시간, 답안 자동 저장·이어하기, 시간 종료 시 자동 제출, 서버 채점, 제출 즉시 점수·정오표를 지원합니다. 출석부(weekend_bety)에는 쓰지 않습니다.

SQL 설치 전에는 등록·학생 응시가 작동하지 않습니다. 스캔 정답표와 임의 배치 정답지는 자동 인식 보장 대상이 아니며 적용 전에 원본 대조가 필요합니다. 이미지 업로드 도중 실패하면 일부 `ko-published/` 객체가 남을 수 있습니다(anon 키로는 삭제할 수 없어 대시보드에서 지웁니다).


## N제 Codex 분석 (2026-10-13)

- `nje.html`의 학년·폴더 → N제 선택 → PDF 가져오기 → 미리보기 → N제에 적용 흐름을 유지합니다. PDF 가져오기 상단에서 `Codex 분석`(기본) 또는 `기존 분석`을 선택합니다. 기존 분석과 Gemini 정답 인식은 그대로 남아 있습니다.
- 로컬 처리기 v4가 필요합니다. 저장소 루트에서 `python -m pip install -r tools/ko-codex/requirements-naje.txt` 실행 후 **진행 중인 분석이 없을 때** 기존 처리기를 종료하고 `start.ps1 -Origin 'https://사용중인-프리뷰-주소' -Background`로 다시 시작합니다. 자동 시작 바로가기는 같은 경로를 계속 사용합니다.
- Codex 연결을 허용한 후 PDF를 올립니다. 먼저 파일을 골랐다면 연결 후 `분석 다시 실행`을 누릅니다. 페이지 새로고침/연결 끊김 후 같은 N제를 선택하고 `결과 다시 받기`로 완료 결과를 받습니다.
- `/jobs?kind=naje`는 암호 없는 30MB/120쪽 이하 PDF 전체를 4쪽씩 Codex로 읽습니다. 문서의 지시문은 실행하지 않고, 표지·개념·문제·빠른정답·해설을 분류합니다. Codex가 원본 번호와 문항/QR 영역 및 정답을 추출하고 Python이 원본 영역을 자릅니다. QR은 zxing-cpp로 실제 디코딩하며 모델이 URL을 생성하지 않습니다. 페이지가 많으면 여러 번의 Codex 호출 및 계정 사용량이 발생합니다.
- 결과는 기존 미리보기/정답 수정 화면에만 넣습니다. `N제에 적용` 전에는 DB·Storage에 저장하지 않습니다. 여러 정답 페이지는 정답 확인 창의 원본 버튼으로 확인합니다. 정답 추측 없이 미인식은 빈칸과 확인 안내로 남깁니다. 원본 번호가 누락되거나 중복/충돌하면 안내하거나 분석을 중단합니다.
- 기존 저장 스키마와 학생 응시/배정은 변경하지 않습니다. 기존 `njeApply`의 전체 문항 교체 방식은 유지하므로 응시 중인 교재에는 덮어쓰지 말고 새 N제로 검토하세요. 임의 양식의 자동 정확성을 보장하지 않으며 원본 대조가 필요합니다.
- 협업 경계: N제 클라이언트는 `assets/naje-codex.js`, 처리기는 `tools/ko-codex/naje_pipeline.py`. `nje.html`에는 스크립트 연결·도움말·버전 표시 및 원본 번호로 정답 매칭/정답 텍스트 안전 표시만 변경합니다. 국어 추출 경로는 그대로 두고 bridge에 N제 작업 종류만 추가했습니다.
- 검증: `python -m unittest discover -s tools/ko-codex -p 'test_*.py'`, `node tools/ko-codex/test_connection.cjs`, jsdom이 있는 환경에서 `node tools/ko-codex/test_naje_ui.cjs`.

## 내신분석표 Codex (2026-10-15)

- `index.html`의 입력 → PDF → 범위 인식 → 문항표 검수 → 총평 생성 → 저장 흐름을 유지합니다. 모달 상단에서 Codex 연결을 허용한 뒤 기존 분석 시작/총평 생성 버튼을 사용합니다. 내신분석의 세 AI 호출은 모두 로컬 Codex로 처리하며 Gemini에 자동 재전송하지 않습니다.
- 로컬 처리기 **v5**가 필요합니다. 실행 중인 작업이 없을 때 기존 처리기를 종료한 뒤 `start.ps1 -Origin 'https://사용중인-프리뷰-주소' -Background`로 시작합니다. 국어와 N제 기능도 그대로 지원합니다.
- `assets/exam-codex.js`는 승인된 origin 연결·작업 폴링·원본 대조 경고를 담당합니다. `exam_pipeline.py`는 암호 없는 **20MB/30쪽 이하 PDF**를 페이지 이미지로 읽습니다. 범위/문항/총평 작업을 `/jobs?kind=exam` JSON 요청으로 받습니다. 기존 Gemini 형식의 호출 인자를 어댑터에서 내부 작업 입력으로 변환하며 그 모델명/토큰 설정은 사용하지 않습니다.
- 문항 분석 전에 별도 Codex 호출로 원본 문항 번호·배점·쪽수 목록을 만들고, 독립적으로 생성한 문항표와 비교합니다. 대조표도 AI 판독 결과이므로 사람이 원본과 검수해야 합니다. 문항 누락·중복·배점 불일치와 불확실한 판독을 표시하며 만점에 맞춰 배점을 보정하지 않습니다. 검수 화면에서 대조표를 펼칠 수 있습니다.
- 근거가 한 문항인 단원도 유지합니다. 난이도는 풀이 단계·개념 연결·발상 필요성 기준이며 30/50/20% 분포를 강제하거나 분포로 경고하지 않습니다. 총평은 사용자가 수정한 문항표만 근거로 작성합니다.
- 작업 로그·페이지 이미지·원본 대조표·완료 결과는 기존 로컬 작업 폴더에 보관합니다. 같은 화면에서 통신이 끊긴 동일 요청을 재시도하면 진행 중 작업을 다시 조회합니다. 페이지를 새로고침하면 입력 폼은 초기화되므로 분석 중에는 유지하세요.
- `exam_analyses` 및 `exam_units` 스키마와 기존 편집/저장/출력 권한 흐름을 유지합니다. SQL 불필요. 저장 버튼을 누르기 전에는 DB를 변경하지 않습니다. 원본 대조표는 로컬 검수용이며 기존 DB 저장에는 포함하지 않습니다.
- 검증: Python 전체 회귀 테스트, `test_exam_ui.cjs` (jsdom), 기존 국어 연결/N제 UI 테스트. 실제 HTTP+Codex는 개인정보 없는 3문항/10점 모의 시험지로 범위·독립 원본 대조·문항표·총평을 검증했습니다. 실제 학교 시험지의 정확도 평가는 별도 샘플로 진행해야 합니다.
